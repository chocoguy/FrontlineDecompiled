### Session 2 (2026-10-11)

- Done: vi, mtx (mtx/mtxvec/mtx44), all 23 OS units, Runtime (__va_arg, global_destructor_chain,
  CPlusLibPPC, NewMore, NMWException, ptmf). 61/100 units started. Left: GX (15), TRK (24).
- OS headers: `include/dolphin/os.h` now has the real OSThread/OSMutex/OSMessageQueue/OSAlarm
  layouts (same sizes as the old opaque structs), OSError handler types, OSFontHeader tail
  fields; new `include/dolphin/os_priv.h` (OS internals, exception numbers) and
  `include/dolphin/base/PPCArch.h` (SPR numbers, HID/L2CR bits).
- MWCC asm maps the `HID2` mnemonic to IABR (SPR 1010). Use SPR numbers in asm
  (`SPR_HID2` = 920, GQR1-7 = 913-919, BATs, SRR0/1); PPCArch.c already `#define`s them.
- Hand-written asm units (OSContext, OS exception vectors, __start, __ppc_eabi_init, mtx PS
  routines) were transcribed with the scratchpad converter `tools/asm2mw.py` (dtk .s function
  -> MWCC `asm` body: labels, numeric SPRs, `.sym` -> `entry`). Data tables (OSFont SJIS maps)
  came from `tools/asmtable.py`. Every asm-function branch target must be declared in C first
  (an undeclared name is taken as a local label: "undefined label 'OSInit'").
- Inlining differences that change call sequences were fixed where the original kept a call
  for a reason (`Run` in OSReboot ends in a hand jump; L2GlobalInvalidate; OSInit's
  ClearArena/OSExceptionInit) using `#pragma dont_inline on` with macros for the bits that
  must still inline. Remaining inlining-only differences (OSThread UnsetRun, OSFont ReadROM,
  vi getTiming) are behaviour-identical and left alone.
- Scb (OSRtc) and Header (OSReboot) are EXI/DVD DMA targets: kept `aligned(32)`.
- `.dtors` holds two `__destroy_global_chain_reference` entries, exactly like retail
  (one from __init_cpp_exceptions, one from global_destructor_chain).
- NewMore.cp only exists to emit the weak std::exception vtable/dtor/what (later units
  reference them); its anchor function is stripped at link. Needs `-Cpp_exceptions on -RTTI on`.
- ELF sections all still 32-byte aligned after the .init units moved to source.

  functions in reverse source order, so sources keep the m2c draft (= original) order.
- Over-inlining fix that works in both modes: wrap the *callee's* definition in
  `#pragma auto_inline off` / `#pragma auto_inline reset` (GXFlush, __SetSURegs,

  inlines one level of self-recursion), TRKTargetAccessMemory, TRKPPCAccessFPRegister).
- targimpl: the register-access helpers (TRKPPCAccessSPR / PairedSingle / SpecialReg) build a
  10-instruction stub on the stack, flush it and call it; they are inline-only in the original
  and stay `static inline` here. TRKTargetAddStopInfo has no return value (header now `void`).
  Like the original, AddStopInfo sends GPRs/FPRs truncated to 16 bits.
